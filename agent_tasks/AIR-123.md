# Expr Patching

Currently expressions (which live in crates with the `expr` prefix) are integrated into configs in a very complex way.

The goal of this task is to isolate these areas and radically simplify working with expressions — make the workflow more transparent and future modifications easier.

# What the task is about

We are performing a significant refactoring and preparing for runtime checks.

1. Rename the current `expr/expr` to `parse`.
   Refactor it significantly.

   Expose only `Parser` (a struct, not a function) which accepts context and parses TOML/string.
   Also expose the AST and `ExprValue` (if still needed — check whether it is).

   Hide everything else in impl modules and do not export it. That is, keep only the interface for:
   string → AST, toml → AST, the AST itself, and a thin `ExprValue` (if still needed).
   The parser we expose must be a struct, not a function.

3. Add `expr/runtime`.
   Move the evaluator and type resolver sections into runtime.
   Make them structs. Create via static methods.
   Cut public interfaces down to the minimum needed for executing an AST and obtaining values/types.

   All other methods go into private.

4. Move the context from `core` into runtime.
   Leave the minimum in core: `ensure_sink_compatible` moves to the `/types` crate.

   `ExpressionContext` now lives in the runtime crate. Remove `eval` from `ExprValue`.

   That is, we create `Evaluator` and `TypeResolver` as separate structs. We pass them a program and context and get back a value.

   The context is isolated and placed in `expr/runtime`.

5. Create `ConfigExprPatcher`.
   What is its purpose?

   Its constructor receives `vec![patterns]` where patterns look like `"name.*.name"` or `"name[*].name"`.
   It walks the config tree and patches values based on expressions.

   Move the `expression.rs` TOML-to/from conversion here as well. Fail if assembly produces invalid TOML.
   (In practice almost everything produces valid TOML — we either convert the type or fall back to a string.)

   Then add this as a step before config assembly. We will construct it explicitly in `main`, specifying the list of patching locations in lexicographic order.

   Try to make patching efficient with minimal allocations. Conceptually this is a simplified tree walk with an Aho-Corasick-style plan (a separate trie structure walked by reference alongside the TOML tree).

6. Remove nearly all expression logic from core.
   `ensure_sink_compatible` and similar functions move to `types` and are called explicitly in default/switch.
   `ExprValue` appears to be unused outside of this.

7. Also scan expr and core for functions that nobody uses and never will
   (not custom functions — those are needed — but obscure public methods, useless one-liners, and functions used only in tests).
   Delete them. (Type inference exists for the next task, so `TypeResolver` must stay even if currently uncalled.)

8. Move `expr/bounds.rs` into func utils. It does not appear to be needed elsewhere.
